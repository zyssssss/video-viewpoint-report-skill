# Video Download Skill

将用户授权的视频链接处理为可追溯的本地 Markdown 转写稿，用于归档、阅读或后续内容分析。

## WHEN｜定场景

适用于用户提供 Bilibili 或 YouTube 链接，并要求下载、提取字幕、转文字、保存逐字稿或基于逐字稿继续整理的场景。默认保存到当前项目的 `video-transcripts/`；用户指定其他目录时遵从其目录。

不把“搜索全站热门视频”当作本 Skill 的默认能力：搜索、排序与下载是两个独立步骤，热度数据必须来自可访问的页面或 API 快照。

完成标准：已明确视频 URL、目标语言、输出目录，以及用户要“字幕原文”还是“本地语音转写”。

## WHAT｜立目标

将【用户有权访问和处理的 Bilibili 或 YouTube 视频链接】处理为【含来源、元数据、带时间戳正文和完整性说明的 Markdown 转写文件】，用于【本地整理、检索与后续分析】。

完成标准：交付一个可打开的 `.md` 文件，并说明使用的是平台字幕还是自动语音转写、覆盖时长和已知缺口。

## HOW｜理规则

1. 确认输入与访问边界。

   - 记录原始 URL、处理日期和用户指定的语言/目录。
   - 仅处理用户提供或明确授权获取的视频；遇到会员、地区、登录、风控或版权访问限制时，不绕过限制。
   - 需要使用浏览器登录态或 Cookie 时，在读取前取得当次明确授权；不要要求用户导出、发送或粘贴 Cookie。

   完成标准：来源 URL 和访问授权状态已写入处理记录；受限内容没有被规避访问。

2. 先采集公开元数据与字幕。

   - 使用 `yt-dlp` 获取标题、上传者、发布日期、时长、描述与字幕轨道信息。
   - 如果有与目标语言匹配的人工字幕或自动字幕，优先下载字幕并保留语言标识；字幕是首选证据，避免无必要的音频下载。
   - 如果字幕可获得但明显仅覆盖片段，记录覆盖范围，并继续执行第 3 步补足缺失部分；不要把片段字幕称为全文。

   完成标准：元数据已保存或写入 Markdown；字幕存在时已判断其语言与覆盖范围。

3. 无完整字幕时下载音频并在本地转写。

   - 用 `yt-dlp` 下载最适合转写的音频流；B 站多 P 内容要逐 P 列出，未经用户选择不得静默合并为一个视频。
   - 使用 `faster-whisper` 进行本地转写。中文默认 `small` 模型；机器性能不足时可降为 `base`，并在成品中标注。保留时间戳。
   - 使用本 Skill 自带的 `scripts/transcribe_video.py`；运行前确认虚拟环境中已安装 `faster-whisper`，不可用时说明缺失依赖并请求安装授权。依赖清单见 `requirements.txt`；已知 faster-whisper 1.2.1 与 PyAV 19 的接口不兼容，因此使用 `av>=16,<17`。

   完成标准：音频仅保存到约定的源媒体目录；转写含时间戳，或明确记录失败原因和未覆盖区段。

4. 生成可审查的 Markdown 成品。

   - 文件名使用 `序号-清理后的标题-全文.md`；若不是全文，使用 `预览` 或 `片段` 标记，避免覆盖同名文件。
   - 顶部包含：标题、来源、平台、处理日期、转写方式、语言、时长/覆盖范围、转写质量说明。
   - 正文按时间戳分段。对听不清、专有名词不确定或多人重叠的内容标记 `[听不清]`、`[待核]` 或 `[重叠语音]`，不靠常识补写。

   完成标准：Markdown 可读取、来源可回溯、全文/片段状态准确，且没有把自动转写伪装成人工校对。

5. 校验并交付。

   - 比对最后一个时间戳与视频时长；若末尾相差明显，标注转写未完成并解释原因。
   - 输出文件路径、处理方式、覆盖情况和下一步可选动作（例如摘要、观点拆解、可视化）。

   完成标准：用户可从交付信息直接打开文件，并能判断内容的完整度与可信边界。

## REFERENCE｜给示例

### 正例

输入：

> 把这个 B 站链接转成全文并保存：`https://www.bilibili.com/video/BV1xx...`，中文即可。

关键执行：

1. 读取公开元数据与中文 CC 字幕。
2. 字幕只有前 85 秒，记录该范围并下载音频完成本地转写。
3. 保存为 `video-transcripts/发现规律-全文.md`，顶部标注“平台字幕 + local faster-whisper 补全；自动转写，未人工逐字校对”。
4. 对末尾时间戳与视频总时长进行比较，确认覆盖完成。

合格输出：

> 已保存：[发现规律-全文.md](/absolute/path/video-transcripts/发现规律-全文.md)。内容覆盖 `00:00:00–00:51:11`；前段来自可访问字幕，其余为本地 `faster-whisper small` 转写。少数不清楚的语句已显式标记，未将其补写为确定文本。

### 反例

错误输出：

> 已生成全文。\n\n`00:00–01:25`（只保存到平台字幕实际覆盖的部分）

问题与替代：

- 将 85 秒的片段字幕说成“全文”，违反完整性标注规则。
- 正确做法是标为“预览/片段”；若用户需要全文且可访问音频，再本地转写并标注其方法和覆盖范围。
- 不应通过导出 Cookie、绕过付费/地区限制或伪造缺失口播来补全文。

## LIMITS｜划边界

- 本 Skill 处理用户提供或明确授权获取的视频，不替代平台全站检索、热榜统计或推荐算法研究；需要筛选热门视频时，另行核验发布时间、播放量和互动快照。
- 仅下载和处理用户有权访问、保存和处理的内容，并遵守平台规则及适用版权要求。遇到登录、地区、会员、DRM、验证码或风控限制，停止并向用户说明所需的合法访问方式。
- 自动转写不是人工校对；噪声、方言、专有名词、多说话人和背景音乐会影响准确率。不得把推测补入转写正文。
- 不上传媒体、字幕或 Cookie 到第三方服务；如用户要求云端处理，先说明接收方、数据范围与成本，再取得授权。
- 不覆盖既有媒体或同名转写稿；新任务创建独立目录或加序号。

### 异常与兜底

- 如果平台提供完整字幕，则直接整理并保存；否则下载可访问音频并本地转写。
- 如果公开访问触发风控、登录、地区或会员限制，则说明具体限制，请用户在其浏览器中合法访问或提供自己有权处理的媒体/字幕/录屏；不绕过限制。
- 如果 `yt-dlp` 失效，则记录报错与版本，建议更新后重试；对于 B 站可在用户同意后改用 `BBDown`，但不静默安装或切换工具。
- 如果 `faster-whisper` 或 FFmpeg 缺失，则列出缺失组件并请求安装授权；不把未成功运行的转写说成已完成。
- 如果只拿到片段字幕或转写中断，则保存明确标为“片段”的文件，写明起止时间和原因。

完成标准：权限、完整性、隐私与平台限制均有明确动作；任何异常输出都不会被误认为完整人工逐字稿。
